## 第三轮：二进制反汇编取证（rev3）

产出：`Manager逆向对比-二进制取证.md`（v2 报告已加勘误头）。

关键结论（均以已发布二进制为准）：
- `CrashDrv.sys` 的 `Verify_CertInfo` 全局 = `0x140039B90`；`KphValidateCertificate` @`0x14002764C` 直接写 `0xF000E401`（active + eCertEternal + eCertMaxLevel + 四项 opt 全开）。
- `%s\Certificate.dat` 字符串存在于 `0x1400313D4` 但**零引用** —— 与源码 `path_cert` 声明残留、读取代码被删完全吻合，是"人工挖空"的铁证。
- `KphVerifyCurrentProcess` @`0x14002785C` = 7 字节 `B8 01 00 00 00 C3`；`KphReadSignature` @`0x1400274F0` 保留全部 I/O 但尾部 `mov eax,1`。
- 修正 v2 两处错误：`KphVerifySignature` 并未改成 return TRUE（完好）；`BCryptVerifySignature` 有 3 处真实调用点，不是零调用。
- 新发现：`CrashDll.dll` 只改了 `SbieApi_*`→`CrashApi_*`(53)，`SbieDll_*`(77, x86 46) 未改名。

方法学教训（重要，后续复用）：
- **线性反汇编会失步**。SandMan.exe 从 `0x14001c7d1` 起解不出指令，只得到 2.9 万条；改为按 `.pdata` 逐函数 disasm 后得到 51.8 万条。任何 PE 反汇编脚本都必须按函数边界切分。
- 判断导入是否可达，要区分 **IAT 跳转桩（`FF 25`）** 与**真实 `call rel32`**；只看 `mem_ref` 会误判为"可达"。
- 常量返回桩可能因叶子函数无 prologue 而不在 `.pdata` 中，需同时做原始字节扫描。
- 工具脚本：`.workbuddy-ai/tmp/rev4.py`（函数级 xref）、`range.py`（区间反汇编）、`callers.py`、`ctx.py`（字符串上下文）。

未能完成：官方安装包是 Inno Setup 6.3.0，`innoextract`/`innounp` 均不支持，无法取得官方二进制做逐字节对照；官方行为均以源码 `sbx_official.zip`（v1.16.5）为准。

### CI 噪音来源
`push:` 不带 branches 过滤时，**dependabot 分支的 push 也会触发构建**；再加上 dependabot 自己的
"Dependabot Updates" run，一次推送能看到 3 个 run。已删 `.github/dependabot.yml`、
`push.branches: [master]`、并删掉远端两个 `dependabot/github_actions/*` 分支。
